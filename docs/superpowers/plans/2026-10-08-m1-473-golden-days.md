# M1 #473: Golden-Log Checks Under 1 s Each Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every test in `tests/unit/golden-log.test.ts` runs in well under a second of its own CPU, with the 5-week golden log still proven end to end, and core stops working out the same state twice.

**Architecture:** core keeps each state's Understanding, and its last advance to a wall time, in `WeakMap`s keyed by course and then by state object. This is the idiom `bucketMemo` already uses, and it is sound because states are never mutated. `npm run golden-log` also writes `packages/core/fixtures/golden-days.jsonl`, with the policy's player as each day begins and the day's counts. `golden-log.test.ts` then checks one day per test: play, replay and walk, chained from a freshly seeded policy to the header's live hash.

**Tech Stack:** TypeScript, Vitest, Node 24 type stripping for probes, break_infinity via `Num`.

**Spec:** Story #473, as rescoped 2026-10-07 after two operator decisions: "Day by day" (23:07 UTC), then "Faster catch-up story" (23:41 UTC), which is #297. Global rule of 2026-10-07: every unit test runs in under 1 s, and no time limit is ever raised.

**Plan written from executed stages.** Both code tasks were built and gated as commits before this plan was written (repo rule: plan code comes from executed stage commits): Task 1 is `684921e` and Task 2 is `fb8a724` on `m1/473-golden-once`. Each step below names what was run and what it printed.

- No timeout added or raised anywhere; every `600_000` this story touches is removed.
- One test per case: a population known before the run (the 35 days, the floors tables) is generated with `it.each`, never looped inside a test.
- Determinism: no new `Math` call in `packages/core/src`; every golden hash unchanged.
- `Refs #473` in every commit, never a closing keyword.

## Review Focus

1. **A state mutated in place after a memo read it.** Expected: impossible. Every `GameState` field is `readonly` down to its records, the core tests `deepFreeze` their states, and a search over every package found no in-place write (positive control: the Player's own `this.state = result.state`). Pinned by `memo.test.ts`: "gives a copy of the state the same Understanding / an equal result".
2. **One state viewed at a new wall time every frame.** Expected: memory stays bounded. `advanceMemo` keeps only the last `(now, result)` per state. Pinned by "works out a new time afresh" and "works out the first time again after a second replaced it".
3. **The same state under two courses.** Expected: each course gets its own answer. Pinned by both "keeps each course apart" tests (mutations M1 and M3).
4. **A day's recorded start loaded from JSON rather than built live.** Expected: identical behaviour. Every day's play, replay and walk start from the parsed line and reach the next parsed start, and the last day reaches the live hash: 141 tests on the first run.
5. **A hand-edited or reordered days fixture.** Expected: refused or caught. `readGoldenDays` refuses a day out of order and an event index that goes back, and a changed count or start fails that day's tests (mutations MD and ME).
